# 🧱 **Section 6 — Building an Image (Dockerfile Basics)**

This section introduces Docker images, Dockerfiles, and how they relate to OS concepts such as layered filesystems and process startup.

---

## 6.1 What Is a Docker Image?

A **Docker image** is:

- A **read-only snapshot** of:
  - a root filesystem
  - installed packages and libraries
  - configuration files
  - default commands/entrypoints
- Composed of multiple **layers**:
  - Each layer represents changes from the layer below (e.g., new files, modified packages).
  - Layers are typically implemented via **union/overlay filesystems** (e.g., OverlayFS).

**OS concept:**

> Images model a root filesystem built from stacked, copy-on-write layers managed by the kernel’s filesystem mechanisms.

---

## 6.2 Containers vs. Images

- **Image**:

  - Static template describing what a filesystem and entrypoint should look like.
  - Read-only layers.

- **Container**:
  - A **running instance** of an image.
  - Adds a **writable layer** on top of the image’s read-only layers.

**Analogy (technical):**

- Image → template of a root filesystem.
- Container → running process tree using that filesystem with namespaces + cgroups applied.

---

## 6.3 The Role of a Dockerfile

A **Dockerfile** is a text file that:

- Describes **how to build** an image.
- Contains a sequence of instructions:
  - `FROM`, `RUN`, `COPY`, `WORKDIR`, `CMD`, `ENTRYPOINT`, etc.
- Each instruction creates a new **layer** in the resulting image (with some exceptions in newer optimizations).

Building an image:

```bash
docker build -t my-image-name .
```

- `-t my-image-name` gives the resulting image a tag.
- `.` points to the **build context** (current directory, including the Dockerfile).

---

## 6.4 Minimal Example: A Simple Ubuntu-Based Image

**Dockerfile:**

```dockerfile
# 1) Base image (defines initial root filesystem + environment)
FROM ubuntu:22.04

# 2) Install packages (creates a new layer)
RUN apt-get update && \
    apt-get install -y --no-install-recommends \
        python3 \
        python3-pip && \
    rm -rf /var/lib/apt/lists/*

# 3) Set working directory inside the image
WORKDIR /app

# 4) Copy application code into the image
COPY app.py /app/app.py

# 5) Define the default command when the container runs
CMD ["python3", "app.py"]
```

**Example `app.py`:**

```python
print("Hello from inside a container!")
```

### Build and run

```bash
docker build -t example-python-app .
docker run --rm example-python-app
```

This demonstrates:

- A base Linux filesystem from `ubuntu:22.04`.
- Package installation in one layer.
- Application code added in another layer.
- A defined startup command (`CMD`).

---

## 6.5 OS View: What Happens When a Container from This Image Runs?

1. The Docker engine:

   - Constructs a unified view of all image layers using an overlay filesystem.
   - Creates the container’s root filesystem from this stack.

2. The kernel:

   - Sets up namespaces (PID, mount, network, etc.).
   - Attaches the container’s processes to relevant cgroups (CPU, memory, etc.).

3. The entry command:
   - `CMD ["python3", "app.py"]` becomes the initial process (PID 1) in the container’s PID namespace.
   - This process runs with the container’s isolated filesystem, network, and other namespace views.

**OS concept:**

> Image layers define the _static filesystem state_; kernel mechanisms define the _dynamic runtime behavior_.

---

## 6.6 Common Dockerfile Instructions (Conceptual Overview)

| Instruction  | Purpose                               | OS/FS perspective                                                       |
| ------------ | ------------------------------------- | ----------------------------------------------------------------------- |
| `FROM`       | Select base image                     | Defines initial root filesystem and environment                         |
| `RUN`        | Execute command at build time         | Modifies the filesystem; creates a new read-only layer                  |
| `COPY`       | Copy files from host into image       | Adds files into the image’s filesystem                                  |
| `ADD`        | Like `COPY`, but can also fetch/untar | Same as `COPY` + extra behavior                                         |
| `WORKDIR`    | Set default working directory         | Changes effective `cwd` for subsequent instructions and container start |
| `CMD`        | Default command when container starts | Defines the process that becomes PID 1 in the container                 |
| `ENTRYPOINT` | Primary entry executable              | Often used for “wrapper” or long-running processes                      |
| `ENV`        | Set environment variables             | Affects process environment inside the container                        |

## 6.7 Example: OS-Focused Image for Observing Processes

**Goal:** Create an image that starts a small monitoring loop printing process and memory info.

**Dockerfile:**

```dockerfile
FROM ubuntu:22.04

RUN apt-get update && \
    apt-get install -y --no-install-recommends \
        procps \
        python3 && \
    rm -rf /var/lib/apt/lists/*

WORKDIR /mon

COPY monitor.py /mon/monitor.py

CMD ["python3", "monitor.py"]
```

**`monitor.py`:**

```python
import time
import os
import subprocess

while True:
    print("=== Inside container ===")
    print("PID:", os.getpid())
    subprocess.run(["ps", "aux"])
    print("========================")
    time.sleep(5)
```

### Build and run:

```bash
docker build -t monitor-container .
docker run --rm -it monitor-container
```

**What this demonstrates:**

- The container’s process list is local to the container’s PID namespace.
- The script’s PID appears as 1 inside the container.
- The host sees the same process with a different PID.

---

## 6.8 Image Layers and Caching Behavior (Brief)

- Each line like `RUN`, `COPY`, `ADD` produces a new **layer**.
- Docker uses **layer caching**:
  - If the instruction and its context are unchanged, Docker reuses the existing layer.
- Order matters:
  - Frequently changing instructions (e.g., `COPY . /app`) should come **later**.
  - Stable instructions (e.g., `RUN apt-get install ...`) should come **earlier**.

**OS concept:**

> Layered filesystems use copy-on-write techniques to minimize duplication; caching exploits immutability of layers.
